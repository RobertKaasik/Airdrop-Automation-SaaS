# AIRDROP-X — чеклист выпуска MVP

Этот список разделяет то, что уже проверяется кодом, и то, что должен сделать
оператор перед ограниченным запуском. Он не заменяет юридическую, финансовую
или security-проверку специалистом.

## Уже покрыто автоматическими тестами

- Приложение отвечает через `/api/health`, база данных и планировщик доступны.
- Страница, статистика и безопасное создание платёжной сессии доступны.
- Цена не принимается от клиента: сервер задаёт сумму и сеть сам.
- Анонимный доступ к защищённым маршрутам, запуску профиля и обзору
  безопасности отклоняется.
- Неизвестный email при сбросе пароля не раскрывает наличие аккаунта.
- Исходный код, `.env`, база SQLite и папка `core/` не выдаются как статика.
- Браузер получает `nosniff`, anti-frame, referrer и permissions headers.
- Словари RU, EN и ZH проходят проверку полноты ключей.

Запуск локальной проверки:

```powershell
$env:AIRDROP_X_TEST_BASE_URL='http://127.0.0.1:8011'
python test_backend.py
python -m unittest -v test_subscription_lifecycle.py test_telegram_wallet_backend.py test_provider_outages.py test_sqlite_backup.py
python test_integration.py
python test_stealth.py
node test_subscription_frontend.js
node test_wallet_session_frontend.js
node test_mobile_responsive.js
node scripts/check-locales.js
node scripts/check-backend-translations.js
node scripts/check-pricing.js
npm run build:ui
python scripts/preflight_production.py
```

## Обязательно сделать оператору до публичного запуска

Подробные команды запуска, мониторинга, аварийного отключения платежей и
backup/restore находятся в [`PRODUCTION_RUNBOOK.md`](PRODUCTION_RUNBOOK.md).

1. **Юридические реквизиты.** Внести юридическое имя оператора, рабочий email
   поддержки, адрес, применимое право, правила возвратов и сроки хранения
   данных в «Политику конфиденциальности» и «Условия использования».
2. **Домен и HTTPS.** Разместить сервис за HTTPS на собственном домене;
   `APP_ENV=production`, `APP_ALLOWED_ORIGINS` — только точные HTTPS-адреса
   сайта. Не публиковать локальный сервер и не включать доверие proxy headers,
   пока reverse proxy не находится под вашим контролем.
3. **Секреты.** Создать новые production-значения для SMTP, Telegram,
   WalletConnect и API-провайдеров. Хранить только в окружении сервера, не в
   репозитории, скриншотах или сообщениях. Ограничить доступ к панели хостинга.
4. **Платежи.** Оставить `SUBSCRIPTION_PAYMENTS_ENABLED=false`, пока точный
   контракт USDC, receiving address, RPC и сеть не проверены на тестнете и
   отдельным ручным тестом. Перед mainnet нужен независимый обзор этого потока.
5. **Резервные копии.** Настроить ежедневный согласованный backup через SQLite
   online backup API, автоматический `PRAGMA integrity_check`, ежемесячную
   проверку восстановления и шифрованное хранение копий. Простое копирование
   только `airdrop_x.db` при работающем WAL не считается backup. При
   одновременных пользователях спланировать переход SQLite → PostgreSQL.
6. **Наблюдаемость.** Настроить доступ к логам, мониторинг `/api/health`,
   оповещение о недоступности и процедуру безопасного отключения платежей.
7. **Поддержка.** Опубликовать официальный Telegram/почту, часы ответа и путь
   для обращения по аккаунту, оплате и данным. Не принимать seed-фразы,
   приватные ключи или пароли в поддержке.
8. **Топология процессов.** Запускать ровно один Uvicorn worker и отдельный
   singleton-процесс `tg_bot.py`. Несколько workers запрещены, пока APScheduler,
   SQLite и in-memory quote/session state не вынесены в общие сервисы.

## Ручной приёмочный прогон

Провести на чистом браузерном профиле и отдельном тестовом кошельке:

1. Открыть лендинг на desktop и телефоне; проверить RU, EN, ZH и GIF-инструкции.
2. Зарегистрировать тестовый аккаунт, затем войти и выполнить сброс пароля.
3. Подключить кошелёк через MetaMask и WalletConnect; убедиться, что интерфейс
   видит только публичный адрес и ни разу не просит seed-фразу или private key.
4. Проверить одну тестовую операцию в тестовой сети и сверить сеть, адрес,
   сумму, контракт и комиссию непосредственно в кошельке до подписи.
5. Отключить кошелёк, выйти из аккаунта и убедиться, что защищённые разделы
   снова требуют входа.
6. Проверить Telegram: подключение, выбранные типы уведомлений и отключение.

## Критерий ограниченного MVP-запуска

Запуск допустим только когда все автоматические проверки зелёные, ручной
прогон завершён, реквизиты и поддержка опубликованы, а платежи либо отключены,
либо прошли независимую проверку именно в той сети и с тем контрактом, которые
будут показаны пользователю.
